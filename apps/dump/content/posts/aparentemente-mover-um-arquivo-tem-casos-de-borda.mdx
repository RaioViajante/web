meus arquivos.

Aparentemente, mover um arquivo foi o bastante para começar a me fazer essa pergunta.

## Pathlib é muito mais agradável do que eu esperava

Uma das primeiras coisas que comecei a usar foi o `Path`.

```python
from pathlib import Path
```

Até agora, eu pensava em caminhos de arquivo principalmente como strings.

Algo como:

```python
"/home/bryan/Downloads/photo.png"
```

O que funciona.

Até você precisar fazer coisas com ele.

Com `Path`, o caminho passa a se comportar mais como um objeto de verdade, e não como uma string que estou cortando desesperadamente.

```python
source = Path("photo.png")
```

Aí posso fazer coisas como:

```python
source.exists()
source.suffix
source.name
```

Sem concatenar strings na mão feito bicho.

Gostei disso imediatamente.

Caminhos de arquivo são o tipo de coisa que parece ridiculamente simples até você precisar fazer literalmente qualquer coisa não trivial com eles.

## Primeiro, só mover o arquivo

A primeira coisa interessante que o `sweep` precisava fazer era muito sofisticada.

Mover um arquivo.

O modelo mental era basicamente:

```text
photo.png
```

virar:

```text
Images/photo.png
```

É só isso.

Então comecei a trabalhar numa função `move_file`.

Eventualmente eu tinha algo com uma responsabilidade mais ou menos assim:

```python
result = move_file(source, destination)
```

Se tudo der certo, o arquivo some da origem e aparece no destino.

E, sinceramente, isso já era satisfatório.

Existe algo estranhamente gostoso em escrever uma função minúscula, rodar os testes e ver que um arquivo de verdade realmente foi parar em outro lugar.

Talvez meus receptores de dopamina estejam completamente destruídos.

## Aí lembrei do arquivo que já está lá

Em algum momento pensei:

> e se `Images/photo.png` já existir?

Minha primeira reação foi basicamente:

"bom... move mesmo assim?"

O que é uma decisão de design fantástica se o objetivo do `sweep` for destruir meus próprios arquivos.

Então, não.

Quero que o `sweep` seja conservador.

Se já existe algo no destino, o comportamento inicial mais seguro é simplesmente deixar tudo como está.

Isso me deu este teste:

```python
def test_move_file_skips_existing_destination(tmp_path):
    source = tmp_path / "photo.png"
    destination = tmp_path / "Images" / "photo.png"

    source.touch()
    destination.touch()

    result = move_file(source, destination)

    assert result is False
    assert source.exists()
    assert destination.exists()
```

Esse foi provavelmente o primeiro momento em que o projeto começou a parecer um pouco mais real para mim.

Não porque seja um código complicado.

É literalmente um teste com dois arquivos vazios.

Mas eu parei de pensar só em:

> a função funciona?

e comecei a pensar em:

> o que acontece quando nem tudo está perfeito?

O arquivo original precisa continuar lá.

O arquivo de destino precisa continuar lá.

E a função deveria me dizer que decidiu não fazer nada:

```python
assert result is False
```

Detalhe minúsculo.

Mas exatamente o tipo de detalhe minúsculo que eu normalmente descobriria depois de quebrar alguma coisa sem querer.

## `tmp_path` parece mágica

Essa também foi minha primeira vez usando `tmp_path` do `pytest`.

Quando vi algo como isto pela primeira vez:

```python
def test_move_file_moves_file(tmp_path):
```

meu pensamento imediato foi:

> de onde diabos veio o `tmp_path`?

Eu não o criei.

Eu não o passei manualmente.

Eu não o importei.

Ele simplesmente está ali.

O `pytest` vê o argumento e fornece um diretório temporário para o teste.

Então posso fazer isto:

```python
source = tmp_path / "photo.png"
source.touch()
```

e criar um arquivo de verdade no sistema de arquivos sem encher o repositório de lixo.

O teste pode interagir com arquivos e diretórios reais e, depois, esse ambiente pode simplesmente desaparecer.

O que é muito melhor do que eu provavelmente teria feito sozinho:

```text
test-files-final-final-2/
```

ali parado para sempre dentro do repositório.

## Aparentemente mover arquivos tem regras

O engraçado é que eu não comecei o `sweep` porque estava procurando um projeto em Python.

Comecei porque estava reorganizando meu computador e cansei da ideia de fazer o mesmo trabalho chato manualmente para sempre.

E agora a parte mais interessante nem é a sintaxe.

Os testes são pequenos.

O que não para de me fazer parar e pensar é tudo o que está em volta do código.

O que acontece se a origem não existir?

O `sweep` deveria criar o diretório de destino automaticamente?

O que acontece quando dois arquivos têm o mesmo nome?

Pulo o segundo?

Renomeio?

Comparo os dois arquivos?

E se eles forem idênticos?

O que exatamente conta como imagem?

Para onde os screenshots devem ir?

As regras devem se basear em extensões?

Nomes?

Datas?

Diretórios?

Metadados?

De repente, "organizar meus arquivos" não é uma operação.

É uma pilha de decisões.

E eu meio que adoro isso.

Porque era exatamente isso que eu queria do projeto.

Eu não queria aprender Python vendo alguém escrever:

```python

```

Eu queria um problema pequeno o bastante para eu conseguir construir, mas real o bastante para continuar criando perguntas que eu não sabia que tinha.
